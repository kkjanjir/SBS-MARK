## 2024-05-18 - [Optimization] Pure Components and Mapping Operations in Bulk Containers
**Learning:** In heavily mapped operations (like rendering bulk print views), components that are wrapped in `React.memo` (like `MarksheetTemplate`) will still re-render entirely for every item if inline static objects (e.g. `{}`) are passed as fallback props. Passing `student={s.student_data || {}}` recreates the object on every single map iteration, defeating the shallow comparison of `React.memo`.
**Action:** When memoizing a component that acts as a template inside a large list or bulk container, always define static default fallback objects (like `const defaultStudent = {}`) entirely outside the component or mapping scope. Use these static references to satisfy the shallow equality check of `React.memo` and prevent massive input lag from O(N) re-renders during unrelated state changes.
## 2024-05-18 - [Optimization] Array References Defeating React.memo
**Learning:** Returning a new array instance from a helper function (like `[...array1, ...array2]`) inside a component's props mapping defeats `React.memo`'s shallow equality check, causing all components in a list to re-render even if the underlying data didn't change.
**Action:** When deriving arrays for props passed to memoized components, ensure the array instance remains stable. This can be achieved by caching the result based on input strings/keys or using `useMemo` with proper primitive dependencies to maintain referential equality.
