## 2024-05-19 - [Performance Optimization: React Memoization in Bulk Print]
**Learning:** In a large monolithic component like `app/page.tsx`, components hidden via CSS (like print containers with `display: none`) still execute full React render cycles. Because the bulk print container (`#print-bulk-container`) maps over `classFilteredStudents` and renders `MarksheetTemplate` for every student in the class, ANY state change in the main component (e.g., typing in a search bar, or changing a single mark in the editor) was causing O(N) re-renders of the heavy template component. Furthermore, inline default objects (like `student={s.student_data || {}}`) bypassed `React.memo` shallow equality, constantly breaking the cache.
**Action:** Extract purely functional, non-state dependent helpers (`getDynamicSubjects`, `getGrade`) and static default objects (`defaultStudentData`, `defaultMarksData`, etc.) outside the main component. Wrap inline helpers (`getClassSubjects`, `getCalculations`, `getClassRank`) in `useCallback` with proper dependencies. Memoize the entire `MarksheetTemplate` mapping operation into a top-level `useMemo` variable (`bulkPrintContent`) and wrap `MarksheetTemplate` with `React.memo()`. This ensures the hidden bulk print elements only recalculate when strictly necessary, preventing severe application-wide input lag.
