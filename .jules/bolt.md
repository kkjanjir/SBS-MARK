## 2024-10-19 - React Memo and Prop Stability Anti-Patterns
**Learning:** Passing inline objects (`{}`) or newly created arrays as props completely bypasses `React.memo`'s shallow equality check, leading to unnecessary re-renders. This is particularly harmful in large mapped lists (like `bulkPrintMarksheets`). Furthermore, heavily mapped elements cause large performance hits if not properly memoized.
**Action:** Extract static default fallback objects (e.g. `defaultStudent = {}`) outside component scope to ensure referential stability. Memoize expensive components used inside lists and wrap the list rendering logic itself in `useMemo`. Memoize helper functions like `getCalculations` and `getClassRank` using `useCallback` when they depend on state.

## 2024-10-19 - Safe Array Dependencies in Memoized Hooks
**Learning:** Returning array literals spread inside a helper function (e.g. `[...fallback.filter(...), ...markKeys.filter(...)]`) breaks referential equality on every call. If this array is used as a prop or dependency, it causes continuous React re-renders or continuous hook re-execution.
**Action:** When extracting functions that return dynamically generated arrays based on object properties (like `getDynamicSubjects`), memoize the wrapper function that calls it using `useCallback`, but be aware that its result array will still be a new reference if the object changes. Therefore, cache the result array itself using `useMemo` so that components receiving it (like `MarksheetTemplate` taking `subjectsList`) receive a stable reference as long as the underlying state hasn't semantically changed.
